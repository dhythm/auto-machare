# Auto Machare — リブランディング設計

## ブランドの考え方

**車と、次の可能性を。**

車を所有する人、必要とする人、運ぶ人をつなぐ。購入・月額リース・残価設定リースを比較し、取引のやり取りから陸送の依頼まで同じ場所で進められるプラットフォームとして再構成した。Machare は MAtCH + shARE で、Agri Machare（農機具版）と共通基盤を分け合う。

トップのメッセージは「車と、次の可能性を。」。最初に目的を選んで検索でき、説明を読み終える前に自分の用事を始められる。

## ドメインの読み替え

| 農機具版                            | 車版                                                                      |
| ----------------------------------- | ------------------------------------------------------------------------- |
| メーカー・年式・稼働時間            | メーカー・車種/グレード（`model`）・年式・走行距離（`mileageKm`）         |
| —                                   | 車検満了日（`inspectionExpiresOn`、任意）                                 |
| トラクター / コンバイン / 田植機 等 | 軽自動車 / 乗用車 / SUV / トラック / バン                                 |
| 個人農家 / 農業法人 / 販売店        | 個人 / 法人 / ディーラー / 中古車販売店                                   |
| 日額レンタル（`rentPerDay`）        | 月額リース（`leasePerMonth`）。期間は 12 / 24 / 36 / 48 / 60 ヶ月から選ぶ |
| レンタル購入（rent-to-own）         | 残価設定リース（residual lease）。買取価格＝販売価格 − 充当額             |
| 運搬の積載重量（`weight`）          | 車両サイズ（`vehicleSize`）と積載台数（`vehicleCount`）                   |

`condition` の4値（未使用に近い / 目立った傷なし / 使用感あり / 要整備）は車でもそのまま読めるため維持した。

### 残価設定リースの計算

既存のレンタル購入の充当率・上限の仕組みをそのまま流用し、語彙だけを残価・買取価格に読み替えた（`lib/residual-lease.ts`）。

- リース料総額 = 月額リース料 × 契約期間
- 充当額 = min(リース料総額 × 充当率, 充当上限, 販売価格)
- 買取価格（残価） = 販売価格 − 充当額

月額を「(販売価格 − 残価) ÷ 期間」で決める残価固定方式は採らなかった。充当型なら既存の計算・テスト・状態遷移・注文生成をそのまま活かせ、出品者が月額と充当条件を自由に決められる。

## 実装上の原則

- 認証・権限・API・データストアの契約は変えず、農機具版から引き継いだ情報階層と導線を保つ。
- 出品者、借手、運搬者は同一アカウントで行き来できる。固定した役割別アカウントへ分断しない。
- 検索の条件やログイン前の車両情報を、次の画面で失わない。
- スキーマは `db/migrations/0001_initial.sql` を書き換えず、`0015_vehicles.sql` / `0016_leases.sql` で列と表をリネームする。
- 変数名・関数名・DB 列名は英語。ローマ字は使わない（`mileage_km`、`lessee_user_id`、`buyout_price` など）。
- 未実装のエスクロー決済、メール通知、保証を実装済みとして案内しない。

## 現在のサービス範囲

コンセプト検証版で、実決済・与信・リース契約の定額請求は未実装。期間指定の月額リース、出品条件に応じた買取充当、取引メッセージ、陸送マッチングを実装済み機能として扱う。

## 画像

商品画像とヒーロー画像は農機具版の素材を車向けのパスへ移して暫定的に流用している（`public/vehicles/kei-car.png`・`sedan.png`・`suv.png`・`truck.png`・`van.png`、`public/brand-hero.webp`）。差し替えは後続作業で、パスとカテゴリの対応（`lib/server/listings.ts` の `imageByCategory`）は変更せずファイルだけ置き換えられる。
